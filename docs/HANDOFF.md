## 已做的決定

- 個人目標超出安全範圍時只警告、不擋下，因為醫師可能給過不同的指示。
- 兩台裝置很少同時使用，但為了預防，設定仍然改成各區段分開同步。
- 體重存在自訂設定（`weightLog` 區段），不放在每日紀錄：只記體重的日子才不會被算進「有紀錄的天數」、拉低運動平均；也不用改 Firestore 規則。代價是兩台裝置同步前都改了體重時，以較新的一次為準。
- 每日目標由固定規則計算，不由 AI 決定：同樣的檢驗每次結果相同，適合長期監控；指引改版時只改 `targetRules.js`。按「套用」才寫入，保留醫師另有指示時手動修改的空間。
- 碳水上限固定 180 g，不依 HbA1c 收緊：指引沒有對應公式，等指引或醫師有具體數字再加。
- 飽和脂肪不另設 20 g 硬上限：20 g 本來就是 2000 kcal 的 10%，只留百分比一個依據。
- AI 服務做成可切換、不直接把 Gemini 換掉：可以比較品質、一邊故障時切到另一邊；Gemini 有免費額度，Grok API 依用量付費。
- 交接資訊放在 repo 裡，跟著 git 同步；因為 repo 是公開的，內容不寫任何敏感細節。
