## 已做的決定

- 個人目標超出安全範圍時只警告、不擋下，因為醫師可能給過不同的指示。
- 兩台裝置很少同時使用，但為了預防，設定仍然改成各區段分開同步。
- 體重存在自訂設定（`weightLog` 區段），不放在每日紀錄：只記體重的日子才不會被算進「有紀錄的天數」、拉低運動平均；也不用改 Firestore 規則。代價是兩台裝置同步前都改了體重時，以較新的一次為準。
- 每日目標由固定規則計算，不由 AI 決定：同樣的檢驗每次結果相同，適合長期監控；指引改版時只改 `targetRules.js`。按「套用」才寫入，保留醫師另有指示時手動修改的空間。
- 碳水上限固定 180 g，不依 HbA1c 收緊：指引沒有對應公式，等指引或醫師有具體數字再加。
- 飽和脂肪不另設 20 g 硬上限：20 g 本來就是 2000 kcal 的 10%，只留百分比一個依據。
- 運動依指引分成三個目標（每日餐後活動、每週有氧分鐘、每週肌力天數），不再把所有運動換算成散步分鐘：有氧和肌力的效果不同，也不能互相取代；強度用講話測試自評，不需要運動手錶。輕鬆的散步不算進每週有氧，但算進餐後活動，因為飯後輕度活動也能降低餐後血糖。
- 今日記錄暫不顯示一天的熱量合計與熱量目標：熱量是 AI 依文字或照片估算，誤差可能很大，顯示合計容易被當成精確數字。目前只在每餐分析卡片顯示估算值，熱量目標只用來算飽和脂肪上限（顯示在檢驗頁的規則卡片）。
- 運動時間用獨立的「開始時間」欄位，不寫在備註：程式要用它判斷是不是飯後，AI 也能準確比對用餐時間；備註是自由文字，程式讀不到。
- 每週統計用「近 7 天」而不是週一到週日：週初時天數少，數字一定偏低，近 7 天每天都能公平比較。
- 舊運動紀錄沒有強度，以中等計算並標成「未分強度」：保持趨勢連續，又看得出哪些是估計。
- 模型名稱空白＝跟隨 App 預設，不把預設名稱寫進使用者設定：模型改版時只要改程式的預設，使用者不用重新設定。Grok 預設維持帶日期的固定版本 `grok-4.20-0309-non-reasoning`，不改用 `-latest` 別名（實測後決定）：回應快、結果穩定，模型不會在不知不覺中換掉；想用新模型時在下拉選單自己選。
- 今日記錄用子分頁，不用可收合卡片或跳轉列（使用者選擇）：一次只看一類最短，分頁上的進度數字仍能一眼看到全天概況。原本只做手機，使用者看過後要求電腦也一樣。
- 模型清單用 API 查詢後讓使用者自己選，而不是拿掉模型選擇：新模型不用等改程式就能用，預設模型停用或故障時也能在手機上自己換；平常收在「進階」裡，不影響一般使用。清單不標示品質與價格，換模型後要先分析一餐確認。
- AI 服務做成可切換、不直接把 Gemini 換掉：可以比較品質、一邊故障時切到另一邊；Gemini 有免費額度，Grok 實測扣的是訂閱月租內含的用量；兩邊分析品質差不多。
- 交接資訊放在 repo 裡，跟著 git 同步；因為 repo 是公開的，內容不寫任何敏感細節。
